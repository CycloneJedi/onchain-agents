Project OnChain / ppu-v20

Pay-per-use (Meter) v2.0

One buyer, one provider, one terms hash and one prepaid tab. The buyer signs running-total vouchers as usage happens; the provider claims what the latest voucher says, up to the balance. Unused funds go back to the buyer with no fee. With dispute hold on, after close the buyer can dispute a held remainder. Deals above 1,000 MUSDC need a named arbiter; exactly 1,000 is allowed without one. Testnet only. Not audited. Not for real funds.

How an agent uses it

  1. Either party calls propose(Terms, deposit). The other confirms the exact terms hash with accept(id, termsHash, deposit) before the offer expires. The buyer's deposit is pulled when the buyer proposes or accepts, so an accepted Meter is open and funded in one step.
  2. Deals above 1,000 MUSDC (ARBITER_THRESHOLD = 1,000,000,000 base units) need a named arbiter; exactly 1,000 MUSDC is allowed without one. Read ARBITER_THRESHOLD().
  3. The buyer may topUp(id, amount) while open, up to the lifetime maximum tab. This changes no term.
  4. The buyer signs EIP-712 running-total vouchers (EOA or ERC-1271). The counter and cumulative amount must both go up; the highest counter governs. Amounts are whole units times the unit price.
  5. The provider (only the provider, never a relay) calls claim(id, voucher, sig, final) or claimLatest(id, final). Net amounts become pull credits.
  6. Either party may close(id) at any time; anyone may from the end time. A claim window follows (default 6 hours, at least 1 hour). Then anyone may finalize(id): the latest voucher is paid up to the balance, the rest is refunded with no fee.
  7. With the dispute module (dispute hold on), after close the buyer may dispute(id, amount) on a held remainder of the final batch inside the claim window. A named arbiter rules an exact amount with resolveDispute; after its window anyone may call resolveByTimeout for a 50/50 split of the held amount (odd unit to the provider).
  8. Both parties can sign one mutual-close message naming the provider amount and submit it with mutualClose.
  9. Everyone withdraws their own credit with withdraw().

Fee preset: 10 bps (0.1%) of what the provider is paid, locked when the offer is made. No fee on refunds. No owner, admin, global pause or upgrade powers in custody. The separate owner powers that do exist (a fee contract whose owner can lower the fee rate and the minimum fee, change where future fees go, and transfer or give up ownership, plus an append-only registry) are disclosed in the build's OWNER-POWERS.md, except that this build's OWNER-POWERS.md leaves out the ownership transfer (see the known limits), whose hash is signed into each offer. ppu-v20 OWNER_POWERS_HASH: 0xfe93e85de9cab87405e0df65d10764a5dc761dde9e7cfac33dcad755372f9d73.

Known limitations

  • On stream-v20 and ppu-v20, the owner of the shared fee contract can also transfer or give up that ownership. Those templates' OWNER-POWERS.md files leave this out. The fee rate locked into an agreement still never changes.
  • A voucher above the tab is accepted but pays only up to the balance; the excess is never owed.
  • A part-batch of units is not payable; vouchers count whole units only.

Also see the limitations for all templates.

Example calls

Set $RPC to a Base Sepolia RPC endpoint (chain id 84532). The address below is read from deployments.json. Use a throwaway test key, never a key that holds real funds.

cast (Foundry)

ADDR=$ADDR
cast call $ADDR "meterOf(uint256)((uint8,uint8,bool,bool,uint32,address,bytes32,uint64,uint64,uint64,uint64,uint64,uint64,uint256,uint256,uint256,uint256,uint256,uint256,uint256,uint8))" 1 --rpc-url $RPC
cast send $ADDR "claimLatest(uint256,bool)" 1 false --rpc-url $RPC --account testnet-throwaway

viem

import { createPublicClient, http } from 'viem'
import { baseSepolia } from 'viem/chains'
const abi = await (await fetch('../abi/onchain/ppu-v20/OnChainMeterV1.json')).json()
const client = createPublicClient({ chain: baseSepolia, transport: http(RPC) })
const result = await client.readContract({
  address: '$ADDR', abi, functionName: 'meterOf', args: [1n] })
// writes: walletClient.writeContract({ address, abi, functionName: 'claimLatest', args: [1n, false] })
