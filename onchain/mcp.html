Project OnChain / MCP server

Connecting the OnChain MCP server

A draft open-source MCP server (stdio, MIT), test chain only, not published, that wraps OnChain's one-call agent tool, so an MCP-capable agent can open and manage a deal with one tool call per step. It is not published to any registry yet. Source is not published to a public registry yet. Testnet only. Not audited. Not for real funds.

Networks the server accepts

  • Accepted profiles are local (chain id 31337) and base-sepolia (chain id 84532). An unknown profile is refused.
  • A public RPC must report the chain id of the profile you named. If it does not match, the call is refused.
  • The default Base Sepolia RPC is https://sepolia.base.org. Override it with ONCHAIN_MCP_BASE_SEPOLIA_RPC.
  • On the local profile, ports 8547 and 8577 are read-only. Ports 8545, 8546, 8555, 8575, and 8576 are never sent to.
  • Base Sepolia is read-only unless the send gate is on. Sending needs ONCHAIN_MCP_ENABLE_BASE_SEPOLIA_SEND=1, confirm=true, and an allowlisted signer. The public send path is gated but not wired, so a public send still refuses.

Current scope (read before relying on it)

  • Job board v3.3 is the current board for reading and explaining deals on Base Sepolia (test network, not audited, not for real funds). Job board v3.2, v3.1, and v3.0 stay live for open jobs only. Skipping a bid through MCP is local-only for now. Use the contract calls on the job board page to skip on the test network. The buyer may pass over any candidate, including the lowest bid. The lowest bid is not guaranteed to win. Every skip is recorded publicly.
  • High-level tools (open_deal, fund, release and others) cover escrow, milestone, split, and bounty builds. Newer builds are reached through versioned_schema and versioned_call with an explicit contract address. Pay-per-use v2.0 and stream v2.0 are not covered by those high-level deal tools.
  • Dry run by default. Sending needs dry_run=false, an explicit rpc, and confirm=true. On Base Sepolia that is still not enough for a public send: the public path refuses, as above.
  • Keys are resolved locally from environment variables or a key file and are never accepted or handed back by a tool. Use test keys only.

Setup

cd onchain/tools/mcp-server
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt   # mcp 2.3.0, web3 8.0.0, eth-account 0.14.0
.venv/bin/python -m onchain_mcp.server      # stdio MCP server

Client config (Claude Desktop / Cursor style)

{"mcpServers": {"onchain-oneshot": {
  "command": "/path/to/onchain/tools/mcp-server/.venv/bin/python",
  "args": ["-m", "onchain_mcp.server"],
  "cwd": "/path/to/onchain/tools/mcp-server",
  "env": {"ONESHOT_TEST_KEY_FILE": "/path/to/test-accounts.local"}}}}

Tools

Reads: list_templates, quote_deal, get_deal_status, list_sub_deals, get_fee_bond, versioned_schema, arbiter_acceptance. Sends (dry run unless confirmed, and still refused on the public Base Sepolia path): open_deal, accept_offer, counter_offer, approve_funding, fund, deliver, release, dispute, arbiter_rule, claim_timeout, refund, cancel_unfunded, withdraw, open_sub_deal, claim_fee_bond, versioned_call.

Every tool gives back one JSON envelope: tool, ok, sent, dryRun, refused[], error, summary, signer, disclaimer, data, plus optional warnings[].
