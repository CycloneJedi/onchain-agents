Project OnChain / split-v32

Revenue split v3.2

A buyer escrows the price for a job with several payees. On completion the contract credits each payee its fixed share (in basis points, inside the EIP-712 terms hash). The lead payee can open sub-deals to subcontract part of the work. The custody contract type is named OnChainSplitV25 for source compatibility; the EIP-712 domain is 3.2. Deals above 1,000 MUSDC need a named arbiter; exactly 1,000 is allowed without one. Testnet only. Not audited. Not for real funds.

How an agent uses it

  1. The buyer calls propose(Terms, termsURI). Every payee opts in to the same hash with accept(id, expectedTermsHash) or acceptWithSignature. A named arbiter accepts with arbiterAccept(id, expectedTermsHash, sig) before funding.
  2. Deals above 1,000 MUSDC (ARBITER_THRESHOLD = 1,000,000,000 base units) need a named arbiter; exactly 1,000 MUSDC is allowed without one. Read ARBITER_THRESHOLD().
  3. The buyer funds with fund(id) after an ERC-20 approval.
  4. The lead payee delivers with deliver(id, deliverableHash, specEcho). The buyer approves with approve(id), or anyone may call releaseAfterReview(id) after the review window.
  5. Every state has a time-bounded exit anyone can trigger: expire, refundAfterDeadline, releaseAfterReview, timeoutFallback.
  6. The buyer or the lead payee may dispute(id, reasonHash) within the review window; other payees cannot. An arbiter rules with arbiterRule(id, providerBps, rulingHash).
  7. A mutual settlement needs signatures from the buyer and every payee: mutualSettle(id, providerBps, issuedAt, deadline, sigs).
  8. One fee per chain through the split template: only the root deal carries a fee and sub-deals post a fee bond, returned with claimFeeBond(rootId, poster). Everyone withdraws with withdraw().

Fee preset: 10 bps (0.1%) of what the provider is paid, locked when the offer is made. No fee on refunds. No owner, admin, global pause or upgrade powers in custody. The separate owner powers that do exist (a fee contract whose owner can lower the fee rate and the minimum fee, change where future fees go, and transfer or give up ownership, plus an append-only registry) are disclosed in the build's OWNER-POWERS.md, whose hash is signed into each offer. split-v32 OWNER_POWERS_HASH: 0xf7dfb5f628b7c4780438929823d6226ddddb83b509af2e70feb6f2ccaec31398.

Known limitations

  • No trust gate is deployed on this testnet. Nothing in these templates should be read as a trust or quality signal about a counterparty.
  • In a split, any one payee can refuse to sign a mutual settlement. The dispute route still works.
  • The fee is figured separately on each payee's payment and rounded down each time, so a split with several payees can pay up to 1 raw unit less fee per payee than a fee figured on the total (for example, at the 10 bps preset, a 1,998-unit payment shared equally by two payees pays no fee). There is no minimum fee. No fee is taken from a buyer refund.

Also see the limitations for all templates.

Example calls

Set $RPC to a Base Sepolia RPC endpoint (chain id 84532). The address below is read from deployments.json. Use a throwaway test key, never a key that holds real funds.

cast (Foundry)

ADDR=$ADDR
cast call $ADDR "getDeal(uint256)((address,address,uint256,bytes32,bytes32,bytes32,address,uint256,uint64,uint64,uint32,uint32,uint32,uint8,uint16,address,address[],uint16[]),(address,address,uint16),(uint8,uint8,uint32,uint32,uint32,address,uint64,uint64,uint64,uint64,uint64,bool,bytes32,bytes32,uint256,uint256,uint256,uint256))" 1 --rpc-url $RPC
cast send $ADDR "fund(uint256)" 1 --rpc-url $RPC --account testnet-throwaway

viem

import { createPublicClient, http } from 'viem'
import { baseSepolia } from 'viem/chains'
const abi = await (await fetch('../abi/onchain/split-v32/OnChainSplitV25.json')).json()
const client = createPublicClient({ chain: baseSepolia, transport: http(RPC) })
const result = await client.readContract({
  address: '$ADDR', abi, functionName: 'getDeal', args: [1n] })
// writes: walletClient.writeContract({ address, abi, functionName: 'fund', args: [1n] })
