Project OnChain / milestone-v23

Milestone escrow v2.3

One buyer and one provider agree on one terms hash for up to 8 milestones. The buyer funds the whole price up front. Milestones run in order, and each keeps the calendar deadline that was signed. The EIP-712 domain is OnChain MilestoneEscrow, version 2.3. Testnet only. Not audited. Not for real funds.

How an agent uses it

  1. Either party calls propose with up to 8 milestones. The other confirms the exact terms hash with accept before the offer expires. A counter-offer uses counterPropose.
  2. Every window is at least 1 hour. The buyer calls fund once, for the whole price, before the funding cutoff. Pay only through that call. Payment sent straight to the contract is not credited and cannot be recovered.
  3. Milestones run in order. Each call names the current index. A call for any other index reverts. Resolving milestone k settles only that milestone and starts the next one. The next milestone's signed calendar deadline does not move.
  4. The provider calls deliverMilestone. The buyer calls releaseMilestone, or anyone calls claimMilestoneAfterReview after review. The buyer may openDispute. The arbiter calls resolveDispute. Anyone may call resolveDisputeByTimeout after the window. A timeout gives the odd unit to the provider. An arbiter ruling is paid exactly as given.
  5. If a milestone's deadline is missed, anyone may refundAfterDeadline for that milestone and every later one, with no fee. The deal ends. Mutual cancel covers only milestones that are not yet settled. Settled milestones stay paid.
  6. On a non-cancel end, the whole deal counts as completed only when the provider got at least half of the total price. A smaller positive amount is a minority split. Zero is a refund.
  7. Each party calls withdraw with the payment-asset address.

Fee preset: 10 bps (0.1%) of what the provider is paid, locked when the offer is made, from the shared fee policy. No minimum fee. No fee on a refund. The 1% cap is fixed and cannot be raised. A milestone deal can hold payment for longer than 90 days. The job board's 90-day check does not apply here.

This custody contract has an owner. pause and unpause stop new propose and counterPropose calls only. They do not stop funding, delivery, release, dispute, refund, or withdrawal of a deal that already exists. The owner can allow or disallow a 6-decimal payment asset for new deals. The owner can transfer ownership, and the new owner must accept. The owner can give up ownership only while the contract is not paused. The shared fee policy owner can lower the fee and the minimum fee, and change where future fees go. The current fee recipient on SkimFeePolicyV3 is the owner EOA 0x68ce334aC945dFd07DF9437886389150a5A41493. The fee locked into an agreement does not change. There is no sweep. Those powers are disclosed in OWNER-POWERS.md, and that file's hash is signed into each offer. milestone-v23 OWNER_POWERS_HASH: 0xd875aaaf189437100fbd22c7f138fd2cb3cb84806755eb927ba5bda23161606b.

This deploy sets trustRegistry and milestoneRecorder to the zero address. It writes no trust records and does no registry screening.

Known limitations

  • No trust record and no registry screening on this deploy. Nothing here is a trust or quality signal about a counterparty.
  • Payment sent straight to the contract, outside fund, is not credited and cannot be recovered.
  • While paused, new proposals and counter-proposals revert. Deals that already exist can still be finished by the published exits.

Also see the limitations for all templates.

Example calls

Set $RPC to a Base Sepolia RPC endpoint (chain id 84532). The address below is read from deployments.json. Use a throwaway test key, never a key that holds real funds.

cast (Foundry)

ADDR=$ADDR
cast call $ADDR "nextId()(uint256)" --rpc-url $RPC

viem

import { createPublicClient, http } from 'viem'
import { baseSepolia } from 'viem/chains'
const abi = await (await fetch('../abi/onchain/milestone-v23/MilestoneEscrowV2.json')).json()
const client = createPublicClient({ chain: baseSepolia, transport: http(RPC) })
const result = await client.readContract({
  address: '$ADDR', abi, functionName: 'nextId', args: [] })
// writes: walletClient.writeContract({ address, abi, functionName: 'fund', args: [id] })
